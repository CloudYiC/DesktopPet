# 软件卸载与关联残留清理

## 工作流程

软件卸载采用三步流程：

1. 读取 Windows“应用和功能”所使用的卸载注册项；
2. 在启动标准卸载前保存当前软件的已知关联位置；
3. 标准卸载完成后，用户逐项审核并选择是否清理残留。

小助手不会静默点击第三方卸载程序，也不会拼接 `rm -rf`、`del` 或其他任意系统命令。
软件清单由 `native/win32_c/src/software_inventory.c` 使用 Win32 C 读取，命令和路径的
重新验证、短期清理计划及资源生命周期由 C++11 `SoftwareService` 管理。

界面会显示卸载项的完整注册表来源和 32/64 位视图。当注册项没有填写
`InstallLocation` 时，原生层会继续读取 `DisplayIcon` 与 `UninstallString`，仅在其中
指向的 `.exe` 确实存在时才使用其父目录作为推断安装位置。

## 通用关联扫描

项目不维护“软件名称 → 固定目录”的专用规则表。每次扫描都会从当前软件生成临时身份：

- 卸载项的显示名称和注册项键名；
- 已验证安装目录的名称；
- `DisplayIcon` 或 `UninstallString` 指向的现存主程序文件名；
- 主程序版本资源中的 `ProductName`、`FileDescription` 和 `CompanyName`；
- 卸载项中的发布者。

扫描只检查有限且可解释的位置：Profile 顶层、LocalAppData、RoamingAppData、
ProgramData、LocalAppData\\Programs，以及当前用户/所有用户开始菜单。首先要求目录名
与产品身份标准化后完全一致；只有顶层目录与发布者身份完全一致时，才继续检查其一层
子目录。不会进行整盘递归、编辑距离或“名字有点像”的模糊匹配。

每条结果会显示具体关联依据和高/中可信度。注册安装位置属于高可信并可默认选择；
Profile、AppData 和 ProgramData 中的结果无论可信度如何都按个人数据处理并默认保留。
名称片段或主程序文件名产生的身份只记为中可信，必须由用户主动选择。

## 原生保护

- 每次标准卸载都会按软件 ID 与显示名称重新读取注册表，WebView 不能替换命令；
- 清理计划使用随机标识，仅允许选择计划中的精确路径；
- 注册项直接提供的标准安装目录，或由确实存在的注册主程序 EXE 推断出的自定义目录，才会加入清理计划；
- 拒绝 Windows 目录及磁盘、用户、AppData、Program Files、LocalAppData、RoamingAppData 和常见个人资料根目录；
- 不跟随目录联接或符号链接统计目标内容；
- 大目录大小统计限制为 100,000 项或约 1.8 秒，并在界面标明“至少”；
- 所选路径使用 Windows 回收站删除，可在误选时恢复；
- 占用中的文件或需要更高权限的路径会保留并报告失败，不会扩大权限或改删相邻目录。

浏览器开发预览只展示示例清单和残留，不会卸载软件或删除文件。原生测试只验证清单
结构和伪造卸载/清理请求会被拒绝，不会在开发机器上执行真实卸载。
