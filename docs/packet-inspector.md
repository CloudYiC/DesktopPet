# 十六进制报文分析器

“十六进制报文分析器”用于把 Wireshark、串口日志或程序日志中的十六进制字节，
整理成可以按偏移检查的报文视图。它补充 Wireshark 的复制与二次分析场景，
不会在没有证据时猜测私有协议字段的含义。

## 输入与识别模式

工具接受连续十六进制、空格分隔字节以及带偏移和 ASCII 栏的 Wireshark hexdump。
输入首先在界面侧规范化，随后桌面版把字节交给纯 C 解析核心。

- `自动识别`：根据版本位和 EtherType 判断 Ethernet II、IPv4 或 IPv6；证据不足时按原始数据显示。
- `Ethernet II`：从二层帧头开始解析，并继续识别 VLAN、ARP、IPv4、IPv6、TCP、UDP 与 ICMP。
- `IPv4` / `IPv6`：适用于只复制了网络层及后续内容的情况。
- `TCP` / `UDP`：适用于只复制了传输层及后续内容的情况。
- `原始数据`：不套用任何标准协议结构，只显示偏移、字节和 ASCII。

解析器始终进行长度边界检查。报文被截断、协议声明长度超过实际输入、IPv6
扩展头暂未展开等情况会显示为警告，而不会越界读取或伪造字段。

## 自定义协议字段

私有协议没有公开结构或 Wireshark dissector 时，仅凭字节无法可靠知道字段名称、
类型和边界。此时可以在未知载荷上添加自定义字段：

- 名称、起始偏移和字节长度；
- 十六进制、无符号整数或文本类型；
- 整数的大端或小端字节序。

自定义字段配置保存在浏览器或 WebView 的本机 `localStorage` 中，不上传报文内容。
点击标准字段或自定义字段都会高亮它覆盖的字节，方便与协议文档逐项核对。

## 实现边界

桌面版的标准协议解析位于 `native/c_core/`，保持 C 接口，C++11 的 `ToolService`
只负责输入限制和 JSON 桥接。网页端没有原生宿主，因此使用等价的 TypeScript
只读解析器。两端都不进行抓包、不访问网卡，也不代替 Wireshark 的重组、校验和
验证、TLS 解密与插件 dissector 系统。
