# 网络调试助手

网络调试助手是云依助手 Windows 桌面客户端内置的本地网络收发工具，用于联调 TCP
或 UDP 服务、观察原始字节并核对发送和接收数量。它不属于独立 `web/` 部署版，运行
时由 React 18 界面通过 WebView2 消息调用 C/C++11 原生网络服务。

## 支持范围

| 模式 | 用途 | 连接与目标 |
| --- | --- | --- |
| TCP 客户端 | 主动连接指定主机和端口 | 一次维护一个 TCP 连接 |
| TCP 服务端 | 在本机地址和端口监听 | 可同时接受多个客户端，并可按目标连接发送 |
| UDP | 在本机端口接收或向指定端点发送数据报 | 无连接；每个数据报保留来源地址 |

三种模式共同支持：

- 文本与 Hex 两种发送输入；Hex 允许使用空格或换行分隔字节；
- 文本发送时可选择不追加换行、追加 LF 或追加 CRLF；
- 文本与 Hex 两种接收显示，便于同时查看可读内容和原始字节；
- 手动发送与可配置间隔的自动发送；
- 收发、连接变化和错误日志；
- RX/TX 收发次数与字节统计，以及清空日志、复制内容。

## 工作区布局（0.12.13）

工作区统一采用纵向三段布局：顶部为全宽连接参数，中间为全宽收发记录，底部为全宽
发送区。连接与发送不再挤在左侧窄列中。日志持续增加时仅记录区内部滚动，不会继续
拉长整个页面。

- 在 1280px、1024px 等空间充足的常规字号窗口中，本地地址、本地端口、远端主机、
  远端端口和连接按钮同行排列；TCP 服务端仅显示其适用的连接字段。
- 发送文本占据可用宽度，行尾、循环发送参数、TCP 服务端“发送目标”和发送按钮
  同行排列；窗口宽度不超过 900px 时，“发送目标”改占下一行，避免参数相互挤压。
- 较窄窗口或放大字号后，参数按可用空间自然换行；连接字段与按钮保持可读字号和
  最小操作尺寸，不通过缩小控件或裁切内容来隐藏溢出。
- 中间记录区按剩余可用高度分配空间；较矮窗口、风险确认或较长客户端列表需要更多
  空间时保留必要滚动，并保留可阅读的日志区域，不裁掉操作项。
- 底部不再常驻“本机处理”等默认说明，实际错误、复制/清空反馈和局域网访问确认
  继续显示。

单次发送最多 64 KiB。客户端未连接、服务端没有目标连接、Hex 输入不完整或端口无效
时，界面会拒绝发送并显示原因，不会静默丢弃输入。

## TCP 数据边界

TCP 提供的是连续字节流，不保留应用层消息边界。一次 `send` 的内容可能被拆成多个
接收块，也可能与随后发送的数据合并到同一个接收块。因此日志使用“接收块”或
“数据流”描述读取结果；如果业务协议按长度、分隔符或固定字段组包，应由用户结合
十六进制报文分析器或自定义协议规则进一步判断完整帧。

UDP 保留数据报边界，日志同时记录该数据报的来源地址和端口。

## 监听与安全边界

- TCP 服务端和 UDP 默认绑定 `127.0.0.1`，只允许本机程序访问；
- 绑定 `0.0.0.0`、局域网网卡地址或其他非回环地址前，必须在界面明确确认；
- 应用不会自动创建、修改或删除 Windows 防火墙规则；
- 关闭工作台或退出云依助手时立即停止网络会话，不保留后台监听；
- 网络请求只接受工作台 WebView 发出的固定命令，不接受宠物窗口或任意网页调用；
- 日志和统计保存在当前运行会话中，不上传到云端。

局域网连接是否成功仍受 Windows 防火墙、路由、目标服务和网络策略影响。需要允许其他
设备访问时，应由用户在了解端口用途后自行配置系统防火墙。

## 使用示例

### 本机 TCP 回环测试

1. 在一个云依助手实例中选择“TCP 服务端”，保持 `127.0.0.1`，设置未占用端口并开始监听。
2. 使用另一个网络客户端连接相同地址和端口。
3. 在文本模式输入内容，按业务需要选择 LF 或 CRLF 后发送。
4. 在日志中核对接收块、来源连接、Hex 字节和 RX/TX 统计。

### UDP 数据报测试

1. 选择“UDP”，设置本地绑定端口和远端地址、端口。
2. 启动会话后，以文本或 Hex 发送数据报。
3. 收到数据报时，根据日志中的来源端点判断回复目标，并核对数据报字节数。

自动发送适合心跳、固定查询帧和稳定性测试。停止会话或离开工作台后自动发送也会停止。

## 暂不包含

当前版本不实现 TLS、WebSocket、MQTT、串口、抓包、组播、脚本执行、云端同步或常驻后台
监听。抓包与协议分层分析仍应使用 Wireshark；云依助手的十六进制报文分析器适合对已经
取得的原始字节做离线拆解和自定义字段标注。
