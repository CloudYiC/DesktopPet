# 网络调试助手与报文模板（0.13.14）

仅 Windows 客户端提供，在“网络协议 → 网络调试助手”打开。原独立“发包工具”
已经合并，不再占用工具卡片；工具总数为 20。连接、报文编辑、发送、报文模板和日志在同一
工作区共享同一会话，不通过两个旧页面的标签切换实现。独立网页端不提供 Socket 功能。

## 合并后的功能

保留 TCP 客户端、TCP 服务端及多客户端选择、UDP 绑定、行尾追加、持续发送、
时间显示和自动滚动；合并报文库及 JSON 导入导出、二进制文件载入、转义字节编辑、
有限次数发送，以及显式组播网卡/TTL/加入/退出设置。旧报文库沿用原存储位置，
打开页面仅只读载入；不会覆盖、清空或自动发送。旧 `packet-sender` 工具 ID 解析为
`network-debugger`，搜索“发包”仍能找到唯一的网络调试助手。

保留接收是为了查看发送后的设备回包，并非每次发送都必须先进入接收/加组模式。
只发组播不要求加组；“加入组播”是用户单独选择的接收操作。

## 操作

1. 选择 TCP 客户端、TCP 服务端或 UDP。当前模式使用实色底、白字与加粗标记，支持键盘切换；
   切换模式本身不自动连接或发送。客户端/UDP 填写目标 IPv4/域名和端口；
   服务端填写本地监听地址与端口，不使用隐藏的远端字段。默认 TCP 客户端目标
   `127.0.0.1:9000`，不会打开即连接。“连接服务 / 开始监听 / 绑定端口”只建立会话，不发送编辑内容。
2. 填写文本、HEX 或转义字节，可载入二进制文件。三种模式转换保持相同原始字节。
3. 选择发送网卡；“发送一次”或 Ctrl+Enter 发送一条；“重复发送”按设定次数顺序发送；
   “持续发送”按间隔一直发送，直到手动停止或发生错误。
   非回环地址弹出居中确认，明确展示目标、端口、网卡、字节数和次数；取消不执行任何网络操作。
4. “停止发送”只取消后续发送，等待已排队的一次完成并保留连接；“停止 / 断开”同时
   关闭会话与释放端口。正常完成后连接保留以接收响应，离开工具即停止。
5. 发送区“报文模板”按钮打开居中管理窗口，在窗口内新建、编辑、搜索、导入、导出和删除。
   编辑模板使用独立副本，保存或取消不会改变当前发送内容或连接；点击“应用到发送区”才回填。
   发送区“另存为模板”将当前参数复制到新模板编辑器；“清空内容”只清空载荷，不重置协议、地址和端口。
   应用只填入编辑区并关闭面板，不自动连接或发送。删除仍需居中确认，不清空当前编辑内容。
6. 组播目标下，可单独点击“加入组播”并确认，开始监听但不发送载荷；“退出组播”同时关闭
   当前 Socket。已经加入的同一会话继续发包不会先退组。

TCP 服务端先监听并等待客户端接入。可指定一个客户端或全部当前客户端，发送开始时
冻结目标列表，逐个等待原生 TX 完成；后接入的客户端不加入当前批次。选中目标断开后
保持“原目标已断开”，必须主动重新选择，绝不自动改为广播。已确认目标断开只停止本批次，
保留仍健康的监听及其他客户端；超时或状态不明才关闭会话，避免迟到 TX 混入下一批次。

右侧仅保留高日志区，TX 琥珀 / RX 绿 / 状态蓝 / 错误红。TCP 接收是字节流
片段，日志条数不是完整应用协议报文数。TX 统计表示本机 Socket 发送完成，不代表远端收到。
日志正文保留至少 320px 的阅读空间（不含内边距），不会被已加入状态或长端点文字压扁。
报文模板不再常驻占位；只有主动打开时显示，模板列表在管理面板内部滚动，不压缩日志高度。
高度不足或字号较大时允许详情最外侧纵向滚动，长消息和更多日志仍在框内滚动。
默认窗口及最大化保持左侧操作、右侧结果；仅较窄窗口上下排列。左侧连接、编辑、行尾、
间隔、次数、发送及停止按钮在同一滚动区内，不再留独立固定发送栏。
向上阅读历史时新消息不抢滚动位置，点击“查看最新数据”回到底部。

## 字节与频率

- 文本使用 UTF-8；HEX 只接受完整字节与空白，拒绝半字节、标点和 `0x` 前缀。
- 转义字节支持 `\00`、`\ff`、`\r`、`\n`、`\t`、`\\`，其他普通文字使用 UTF-8。
  无效转义会报错，不静默修改；非法 UTF-8 二进制不能转换为文本，只能保持 HEX/转义。
- UDP 单次上限 65507 字节，TCP 65536 字节；零字节允许保留草稿，不允许发送。
- 次数 1–1000，间隔 50–86400000 毫秒（最长 24 小时），保留原网络调试的 50ms 下限。下一条从上次发送确认后开始计时，
  使用串行等待，不重叠请求；这是调试重发，不是高精度流量发生器。TCP 保持同一连接。
- 执行时冻结协议、目标、字节、次数与间隔，禁用相关编辑；超时、连接失败不自动重试。
- 原生 Start 只表示启动请求已接受，等待 UDP ready/TCP connected 后才排队发送；发送排队
  也不等于 TX 完成，界面等待原生计数更新。停止或离页使旧异步回包失效。
- 行尾选“不添加 / LF / CRLF”；每次发送只追加一次，字节上限包含行尾；切换文本/HEX/转义
  模式只转换原始正文，不把行尾反复写进草稿。空内容仍可单独连接/监听。

## 地址与组播边界

默认使用“自动选择网卡”（`0.0.0.0`）与端口 0（系统分配），目标仍是 `127.0.0.1:9000`。
发送网卡下拉框通过 Windows GetAdaptersAddresses 只读枚举本机已启用 IPv4 地址，
显示例如“WLAN（192.168.x.x）”；不会探测远端设备。非回环网络操作必须确认，停止、
失败后重新建立会话或变更目标/网卡/端口/TTL 后重新确认；仅刷新和选择网卡不会连接。

旧报文库中的 127.0.0.1 不静默重写。向组播目标发送旧草稿时，确认框明确提议自动网卡，
只有确认才修改当前草稿，不改目标端口/载荷或已保存条目。丢失的网卡会提示不可用并拒绝发送，
不悄悄换网卡。系统自动路由不适合所有多网卡环境，设备在哪块网卡请选择该网卡。

对 IPv4 UDP 组播，发送网卡通过 `IP_MULTICAST_IF` 设置，TTL 通过 `IP_MULTICAST_TTL`
设置（0–255，默认 1）。加组用同一网卡执行 `IP_ADD_MEMBERSHIP`，只有原生成功后才显示
“已加入”；退出执行 `IP_DROP_MEMBERSHIP` 并关闭 Socket，关闭也会释放失效网卡的成员关系。
本版支持单个活动接收组，不是多个组同时管理。发送不要求先加组；加组也不代表已发送报文。
加组会重建 UDP Socket：相同目标/网卡/TTL/请求本地端口下，保留已经分配的源端口，
不因原来填写 0 就再次随机换端口。确认框提示短暂重建可能错过入站数据，发送/接收计数重置；
后续发送继续使用已加入的 Socket。若重绑端口失败则显示错误，不静默换成另一个端口。

组播接收 Socket 绑定 `0.0.0.0`，发送/接收接口另行指定。本地端口与目标端口独立：
若设备向组地址的 24576 端口广播组播消息，应将本地端口设为 24576（可点“同目标端口”）；
若设备回复发送方临时端口，可保留本地 0。确认框和状态区会显示实际监听端口。
不会自动抢占端口、开启地址复用或修改防火墙；其他工具占用同一端口会得到绑定错误。

截图中 Packet Sender 为 `224.20.20.20:24576`，旧云依界面却是目标端口 9000 且绑定
127.0.0.1，因而尚未发送。本次不将 24576 写死为通用默认，用户需填写正确端口并粘贴
同一份 HEX；21 字节默认问候文本也不等于截图中设备所需的二进制载荷。

不提供广播开关、IPv6、原始 Ethernet/IP 头注入、PCAP 重放、HTTP/HTTPS/TLS。
输入的是 TCP/UDP **载荷**，IP/TCP/UDP 头由操作系统生成，并非直接重放完整抓包帧。

复用现有 C/C++11 Winsock 服务与 dashboard-only 桥，不新增驱动、提权或协议依赖。
现在只有网络调试助手管理这一个原生会话，离页立即停止旧会话。

## 本机报文模板与兼容性

界面从“已保存报文”更名为“报文模板”，底层仍以 `cloudyi.packet-sender.library.v1`
保存于客户端 WebView2 的 localStorage，最多 100 条，不修改存储键或 schema，不要求重新录入，
JSON 总大小不超过 1 MiB。旧 schema-1 数据在内存补 TTL 1、不添加行尾，旧 TCP 映射为
TCP 客户端，UDP 仍是 UDP；地址、端口与字节不变，不自动写回存储。新条目可以保存
`networkMode` 与 `lineEnding`，不包含动态客户端 ID；载入服务端模板不会自动监听或发送。
仅保存明确点击“保存”的配置和载荷，不持久化运行状态、已加入状态或局域网确认。
载荷不加密，不要保存密码或其他敏感信息。JSON 导出可作为迁移备份，导入只新增报文。

导入整库验证格式、字节、边界、ID 和时间；重复 ID、未知字段、损坏 JSON、超大文件全部拒绝，
不部分导入，不覆盖已有条目。读取损坏时保留原始库且禁止覆盖，导出可取得原始备份。
浏览器存储写入失败会显示错误，只有成功写入才更新界面。内存日志最多 5000 条并按约 4 MiB
字符预算裁掉最旧记录，不写入本地数据库。

## 验证

- `node scripts/test-packet-sender-model.cjs`：纯模型、严格字节转换和库合并边界。
- `node scripts/test-network-debugger-ui.cjs`：统一三模式、服务端多目标与目标断开、持续/有限
  发送停止保连接、行尾和模板保存、迟到排空日志保留、历史阅读与不同尺寸字号布局。
- `node scripts/test-packet-sender-ui.cjs`：隔离浏览器 + 模拟原生桥，验证发送、取消、保存、
  导入、生命周期和默认/最大化/窄窗口布局；覆盖日志最低正文高度、状态换行、空模板、
  多条模板内部滚动、模板面板开关/载入/删除焦点、发送按钮随左栏滚动及矮窗口外层滚动，
  不访问实际 LAN/设备。
- `MiloNetworkDebugServiceTests`：仅临时回环端口，覆盖 UDP 立即排队、切换目标、计数重置、
  无效/超长载荷、停止后禁止发送，以及原有 TCP/UDP 回归；新增只读网卡枚举、网卡/TTL
  校验、回环绑定 Socket 上读取 IF/TTL 设置结果、错误成员关系请求拒绝。
- 前端生产构建、Release 原生构建和 CTest；安装包由最新产物生成。构建验证不等于在用户
  电脑执行安装/卸载；本轮未对实际组播网络或硬件做通信测试。

组播成功/失败、确认、取消、RX、退组与既有成员关系发包复用均使用合成原生桥验证；
本轮没有向用户物理网卡发出 IGMP 加组或组播流量。实际设备、交换机、Wi-Fi 组播支持、
防火墙与回包端口仍需在用户网络中验证，不能用界面的 TX 计数代替远端收包证明。

实现依据：[Windows IP 层 Socket 选项](https://learn.microsoft.com/en-us/windows/win32/winsock/ipproto-ip-socket-options)、
[IPv4 接收成员关系](https://learn.microsoft.com/en-us/windows/win32/api/ws2ipdef/ns-ws2ipdef-ip_mreq)。
