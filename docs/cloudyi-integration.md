# CloudYiCSC 桌面功能合并说明

## 目标

可爱依依继续负责桌面陪伴、提醒和角色互动，CloudYiCSC 的桌面工具按模块逐步迁入同一个工作台。当前版本不引入 Go，也不启动本地 HTTP 服务。

## 界面结构

侧边栏按以下顺序组织：

1. CloudYiCSC：工具首页、数据处理、网络协议、系统工具和文件处理。JSON、正则、文本比较与数据库工作室统一归入“数据处理”；图片转换器统一归入“文件处理”；不设置独立代码、AI、图片、数据库或效率文档分类。
2. 可爱依依：今天、全部事项、宠物状态和设置。
3. 模块管理：只展示已经内置并可实际使用的本地工具。
4. 工作台中心：固定在底部，管理主题、字号、模块状态和本机数据。

Light 主题沿用可爱依依的奶油白、暖橙与青绿色。核心颜色集中在
`frontend/src/Root.module.scss` 的 `--theme-*` 变量中，后续可以整体换色；Dark 主题暂不在本阶段实现。

## 原生边界

```text
React 18 + TypeScript + SCSS Modules
              |
       WebView2 JSON 消息
              |
      C++11 ToolService 适配器
              |
      纯 C CloudYi 算法核心
```

- `native/c_core/`：只放不依赖 Windows、WebView2、C++ STL 和 JSON 库的可移植 C 代码。
- `native/src/ToolService.cpp`：检查工具标识、操作标识、输入大小和 UTF-8 输出，再调用 C 接口。
- `native/src/Application.cpp`：只接受明确允许的 `tool.execute` 消息，不允许前端传入任意函数名、文件路径或系统命令。
- `frontend/src/toolbox/`：工具目录和工作区；样式全部使用 `*.module.scss`。

选择 C++11 的场景包括 Win32 资源生命周期、WebView2 回调、UTF-8/UTF-16 转换、JSON 消息和异常边界。其余可独立测试、可跨平台复用的算法优先使用 C。

## 工作台中心设置

能够真实工作的常规、模块、存储和关于信息已经组合到侧栏底部的“工作台中心”：

- 暖杏、云青和柔粉三套完整浅色主题；
- 紧凑、标准和放大三档全界面字号；
- 记住上次页面与工具分类；
- 本地模块启用状态、事项/角色数据概览和当前版本信息。

主题、字号和上次页面由 C++11 写入 SQLite 的 `app_settings` 表。没有后端的登录注册、在线更新以及尚未完成的深色主题不会出现在当前工作台中。

尚未完成的工具不会作为占位卡片显示。浏览器开发预览为
Base64、Hex、URL、SHA-256、数字、时间戳、UUID 和密码提供前端回退；正式桌面版统一
经过 C 核心。MD5 浏览器预览不回退，以免引入第二套实现。

## 后续迁移规则

1. 先确认 CloudYiCSC 原模块的许可、输入输出和测试向量。
2. 无平台依赖的算法迁入 `native/c_core/`，头文件使用 `extern "C"` 兼容 C++ 调用。
3. 需要路径、窗口、系统权限或复杂对象生命周期时使用 C++11，不使用 C++14/17 API。
4. 在 `ToolService` 增加固定分支和输入上限，不暴露任意命令执行能力。
5. 为 C 核心补充已知向量单元测试，为 React 工作区补充构建与交互验证。
6. 工具真正可用后，才加入工作台目录。
