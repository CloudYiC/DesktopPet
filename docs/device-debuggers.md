# 串口、MQTT 与 Modbus 调试助手（桌面 0.13.10）

三个工具位于“网络协议”，随 Windows 安装包提供并直接打开。独立 `web/` 不增加这些
设备客户端；浏览器开发预览只能检查布局，不会伪造串口打开、Broker 连接或设备响应。

## 共用操作与边界

- 紧凑的“返回工具列表 / 工具名”顶部与现有工具一致，外层侧栏及客户端默认大小不变。
- 常用连接参数紧凑分组；收发记录、消息与寄存器结果在内部滚动，不随记录数量拉长页面。
- 窄窗口或展开高级设置时允许自然滚动，不通过隐藏按钮或缩小字体强行塞入。
- 原生层使用独立、有界的工作队列与后台线程；用户界面线程不执行设备收发。
- 离开工具、关闭工作台或退出应用会停止对应会话；不会添加系统服务或修改防火墙。
- 工具只连接用户明确选择的 COM 端口或填写的目标，不自动扫描网络或向设备试写。
- 日志和本次通信参数只保留在当前工具会话；复制按钮才会写系统剪贴板。

## 串口调试助手

左侧选择 COM 端口、波特率、数据位、校验位、停止位与流控，然后打开串口。
打开后锁定连接参数，修改前需先关闭。DTR/RTS 收入高级设置，避免把硬件控制位
误当作普通发送按钮。端口被占用、不存在或设备被拔除时显示实际 Win32 错误。

收发区以不同颜色区分 TX 和 RX，可切换文本与 HEX、时间、自动滚动、复制和清空。
串口本质上也是字节流，接收块不代表自定义协议的完整一帧。普通文本按 UTF-8 编码显示，
需要无损检查时使用 HEX。发送区提供行尾和定时间隔，循环发送关闭或离开页面后停止。

HEX 输入需要完整的字节，非法字符、奇数半字节和超出单次容量的输入会被拒绝。
串口名称只接受 COM 编号，不提供任意 Windows 设备路径访问能力。

## MQTT 调试助手

当前为 MQTT 3.1.1 客户端，不是 Broker 管理器。左侧配置 Broker 地址、端口与客户端
ID；认证/TLS 和会话参数在展开区域。首版使用 Clean Session 新会话，不恢复断线前的
持久订阅或未确认消息；重连后重新订阅。密码不写入本地持久化配置、普通消息记录或
错误日志。TLS 必须验证服务器证书和目标名称，不提供默认跳过证书错误的路径。

左侧集中连接、主题订阅与发布，右侧优先显示高消息列表；不再让连接横跨顶部、
发布横跨底部，再把有限的消息区上下切半。每条直接显示时间、收发方向、主题与载荷摘要，
收到消息使用绿色，发布消息使用蓝色，同时标注 RX / TX，不只依靠颜色辨认。
按主题/内容关键词与收发方向筛选；完整载荷仅在显式选中消息后展开，可以收起。
默认窗口和宽窗口列表与详情左右并列，更窄时才使用可收起的侧面区，不切掉列表高度。
自动跟随与接收相互独立：关闭跟随或向上阅读历史不会停止接收，新消息提示可回到最新；
新消息不自动替换正在查看的消息，过滤或保留上限淘汰不自动切到另一条消息。
消息最多保留 2000 条，并按载荷与解码/搜索字符串计算 4 MiB 缓存预算；超过上限时淘汰最旧记录。
断开后保留当前消息用于检查；显式重新连接开始新历史，原生未读队列也按新会话隔离。
迟到轮询仍保留本会话已取出的消息，但不能把新的连接、订阅或计数状态覆盖成旧值。

支持 QoS 0/1/2 与保留消息。订阅主题过滤器支持 MQTT 的 `+`/`#` 通配符；发布主题
不允许这两个通配符。收到的消息保留实际 Topic、QoS、Retain 与载荷字节，而非假定
所有载荷都是 JSON；文本和 HEX 视图都可使用。

认证被拒、订阅失败、证书错误、超时或连接丢失会明确反馈。连接成功不等于消息已到达
最终设备；QoS 确认仅表示本客户端与 Broker 之间对应协议阶段的完成。

## Modbus 调试助手

Modbus 是应用协议，不等同于串口工具。RTU 使用串口帧和 CRC，TCP 使用网络连接和
MBAP 头；两种模式分别显示自己的连接参数。首版 TCP 目标使用 IPv4/IPv6 数字地址。
RTU 的串口需按设备文档匹配波特率、校验位及停止位，设备 ID 使用 1–247，不发送广播。

功能码：读线圈 `01`、读离散输入 `02`、读保持寄存器 `03`、读输入寄存器 `04`、
写单线圈 `05`、写单寄存器 `06`、写多线圈 `15`、写多寄存器 `16`（以上为十进制编号）。

“协议地址”明确从 0 开始。40001 等参考编号只是便于对照手册的换算，不能与实际请求
地址混用。显示的原始数值不擅自赋予温度、电压等含义；设备的单位、比例系数及跨多个
寄存器的数据布局仍以厂商手册为准。

读取支持有限次数的超时重试与可停止轮询。写入默认关闭，开启“允许写入”后，每次
写操作仍需确认传输类型、目标、设备 ID、功能码、起始地址、数量和全部值。原生层
重新检查功能码、地址、数量、值范围和确认标记。写请求不会自动重试；发送后连接丢失
或超时不能宣称写入成功，需提示结果不确定并建议先读取核对。

结果表显示协议地址、参考编号、HEX、整数和更新时间；地址/值筛选便于在大量结果中定位，
“复制当前结果”仅复制当前筛选后可见的行，“只看变化”可快速聚焦本次改变的数据。
线圈值以明确的 ON / OFF 与颜色呈现；同一连接、功能及地址范围的连续读取突出变化值，
不同设备或不同请求范围不混作比较基线。刷新中保留上一结果并标记状态；停止轮询后仍可浏览。
原始报文默认只显示紧凑标题与摘要，按需展开后独立滚动；阅读历史不自动跳到底部。
TCP 响应检查事务 ID、协议 ID、长度及设备 ID，RTU 响应检查完整长度与 CRC；异常响应
显示 Modbus 异常码，不作为正常寄存器值。

## 调试工作区布局（0.13.10）

- 串口、MQTT、Modbus 与网络调试助手在视口宽度超过 900px 时左右分栏：串口左侧为
  连接及发送、右侧为收发记录；Modbus 左侧为连接和请求/写入参数，右侧为结果表及
  原始报文。默认窗口和最大化时可同时操作和观察结果。
- 宽度不超过 900px 才上下排列；1024 × 640 与 920px 等较窄但仍可用的桌面视口
  保持双栏。较矮窗口及展开 DTR/RTS、超时与重试等参数时，左侧允许必要的内部滚动，
  不挤压或移动右侧结果，也不缩小字体、裁掉按钮来假装没有滚动。
- 大量日志与寄存器仅使其自身列表滚动；矮窗口、较大字号或展开辅助区域时保留自然外层
  滚动。外层侧栏、客户端首选尺寸与原生通信协议不变，Modbus 写入仍使用客户端中央确认。
- 合成 UI 回归覆盖 1280 × 762 默认视口、最大化、两种字号、缩放等效/窄视口，
  以及 500 条串口日志、125 行 Modbus 结果。测试不访问真实串口或工业设备。

## 验证方式

- `node scripts/test-debugger-bridge.cjs`：合成 WebView 消息的请求关联、并发、错误、超时、
  浏览器不可用状态，不连接真实设备。
- 原生测试：协议向量与错误边界，以及仅绑定本机回环地址的合成 Broker/Modbus 设备。
- UI 回归：使用独立浏览器配置和合成原生桥，检查默认/窄屏布局、参数交互、日志内部
  滚动、写入确认和离开页面的停止请求。
- `test-mqtt-messages-ui.cjs` 覆盖大量消息摘要/筛选、详情选择、自动跟随与历史阅读、
  有界消息保留及默认/最大化/窄窗口两种字号；`test-modbus-ui.cjs` 覆盖变化基线、
  刷新保留结果、筛选、线圈状态、原始日志折叠与既有写入确认。
- 自动化测试不能代替不同 USB 转串口驱动、RS-485 收发器和实际硬件的兼容性测试。
  未连接真实硬件时，不将协议/模拟测试表述为已完成真实设备验证。
